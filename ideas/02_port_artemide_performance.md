# Идея 02 — перенести в KAST оптимизации производительности из Artemide

> **Создан:** 2026-09-26 (агент, при выборе основы форка) · **Родитель:** `ideas/01_reconnect_grace_period.md`
> (выбор базы) · **Статус:** ❓ ожидает одобрения владельца — агент не реализует до одобрения
> · **Вовне:** решение владельца

## Боль

Владелец играл через Artemide (`derflacco/moonlight-android`). KAST построен на Artemis, где нет 31 коммита
Artemide о плавности и задержке. Если владелец привык к поведению Artemide, KAST может ощущаться хуже.

**Чем проверим, что сработало:** на телефоне владельца KAST с перенесёнными правками идёт не хуже Artemide по
счётчикам оверлея производительности (задержка декодера, пропуски кадров) в одной и той же игре и сети.

## Что есть в Artemide сверх Artemis (сверка GitHub 2026-09-26: ahead 31 / behind 76)

- привязка «горячих» потоков к большим ядрам процессора, расширенное определение кластеров;
- аудиопоток с наивысшим приоритетом реального времени;
- «Snappy Input» (две ревизии);
- мягкий слив очереди в режиме Low-latency + CAP_FPS; уменьшение колебаний частоты;
- AV1 на MediaTek: RFI через vendor keys и AdaptivePlayback; low-latency после старта кодека;
- LFR — режим темпа кадров (описан в README Artemide).
