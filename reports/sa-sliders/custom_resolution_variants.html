Своё разрешение: варианты окна

Список «Разрешение» остаётся, как хочет мейнтейнер: 360p…4K и строки «Нативное». Меняется только окно строки «Пользовательское разрешение», где сейчас одно текстовое поле и нужно вписать «1920x1080» латинской «x». Окна живые: жмите соотношения, «−» и «+», засечки, замок, вписывайте свои числа.

Что показала разведка (подробно с источниками — researches/03)

  • Ни один клиент стриминга не выбирает разрешение шкалой. Moonlight для ПК, Parsec, Shadow, GeForce NOW, PS Remote Play, Steam Link, Windows App: везде список готовых, «как у устройства» и «своё». Тут мейнтейнер прав.
  • Moonlight для ПК вводит своё разрешение двумя полями с неизменной «x» между ними: только цифры, от 256 до 8192, «OK» не нажимается, пока числа неверные (SettingsView.qml). Это родитель Super Artemis, такой довод мейнтейнеру сильнее любого нашего.
  • Соотношение сторон сначала, потом размер: так в RetroArch, Winlator, в меню многих игр. В Moonlight для Android уже лежит неотвеченный запрос на своё разрешение по соотношению экрана телефона 20:9 (PR #1349). Когда удалённый рабочий стол Microsoft на Android давал только соотношение экрана устройства, пользователи жаловались: значит, «Нативное» должно быть одним из вариантов, а не единственным.
  • Замок пропорций между двумя полями: Photoshop, Canva, Figma. Вписали ширину, высота считается сама.
  • Числа должны быть чётными, лучше кратными 8: кодеки кодируют блоками 16×16 и 32×32. Android умеет спросить у декодера телефона, какие размеры он примет.
  • Шкала с подписями в Android возможна, но подписи под засечками придётся рисовать самим, и засечек не больше восьми. Примера среди клиентов стриминга нет.
Устройство (меняет «Нативное»):

В1. Как в Moonlight для ПК

Два поля только под цифры, между ними «×». «OK» не нажимается, пока числа пустые, нечётные или вне 256…8192. Ничего больше.

Где так: Moonlight для ПК (дословно). Самый маленький PR и самый сильный довод для мейнтейнера. Соотношения сторон нет.

В2. Соотношение и замок рекомендую

Сверху соотношение сторон, по умолчанию «Нативное» (экран устройства). Замок закрыт: вписали ширину, высота посчиталась по соотношению и округлилась до кратного 8. Открыли замок — поля свободны.

Где так: RetroArch и Winlator (сначала соотношение), Photoshop, Canva, Figma (замок), поля и проверка — Moonlight для ПК. Решает случай телефона 20:9 из PR #1349.

В3. Соотношение и шкала с подписями примера нет

Ваша идея: соотношение сверху, под ним «−», ширина × высота, «+», ниже шкала. Засечки и подписи меняются вместе с соотношением. Шкала только заполняет поля.

Где так: среди клиентов стриминга нигде. Части есть: соотношение сначала (RetroArch, игры), шкала рядом с полем для точного числа (Material). Мейнтейнер может снова сказать «нет» шкале.
