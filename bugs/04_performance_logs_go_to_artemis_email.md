# Баг 04 — «Поделиться журналами производительности» шлёт журналы KAST на почту разработчика Artemis

**Status:** 🔴 OPEN — ждёт решения владельца (куда слать или убрать пункт)
**Version/build:** KAST Debug 20.2.6 (Artemis `c5cf27f4` + `1ba2dfaa`) · **When/context:** 2026-09-26, найден агентом при подсчёте непереведённых строк (баг 03)
**Severity:** S2 (чужое имя в продукте: данные пользователей KAST уходят в сбор статистики Artemis)
**Fixing:** после ответа владельца — одной правкой строки или пункта настроек
**Fix accepted when (observable):**
- Ситуация. KAST на Титане, «Настройки» → пункт «Поделиться журналами производительности».
- Действие. Пользователь нажимает пункт.
- Результат. Письмо либо адресовано тому, кого назвал владелец, либо пункта в настройках нет (по решению владельца).
- Проверка. `git grep -n "artemistics" app/src/main` — пусто (или только в комментарии об истории); снимок экрана пункта.

## Symptom
`app/src/main/res/values/strings.xml`: `email_recipient` = `artemistics.logs@gmail.com`;
`StreamSettings.java:786` (`share_performance_logs`) собирает журнал `PerformanceDataTracker`, пишет его в
`artemistics_logs.txt` и открывает почтовый клиент с этим адресом. Рядом в `res/xml/preferences.xml:938` — ссылка на вики
Artemis «Performance-Statistics-Collection».

## Root cause
Наследство форка: Artemis собирает статистику производительности своих пользователей на свою почту. В KAST это значит, что
журналы KAST попадут в статистику Artemis — то, о чём автор Moonlight просит форки не делать (комментарий в `app/build.gradle`).

## Fix plan — варианты для владельца (в интервью, когда он у машины)
- убрать пункт из настроек KAST;
- слать на адрес, который назовёт владелец (агент адрес не выбирает);
- оставить Artemis — если владелец хочет помогать их сбору статистики.
