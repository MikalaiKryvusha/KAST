## 1. Work

The resume loop of plan 06 (`plans/06_epic02_F3_resume.md`, steps 3–4): when the control transport dies inside the grace
period (end class `transport`), KAST keeps the stream screen, stops the dead connection, and restarts the same `NvConnection`
with a fresh decoder after a backoff (`KastReconnectPolicy.retryDelayMs`) until the stream is back or the grace period is
over. Basis: plan 06 acceptance criteria 1 (K2) and 7 (the log); `testcases/TC_reconnect.md` K2.

## 2. Contour

(`control_peer_timeout = 60000`), app «Desktop». Grace period 60 s (default), the debug instrument
`kast_debug_enet_timeout_seconds = 10` written through `run-as` (the client transport dies at 10 s while the host still holds
the session), retry interval 3 s (default, no settings UI yet). The loss: `tools/droprun.ps1` (Tailscale down on the host PC).
REAL WORLD: accumulated — the owner's host with its running session history, the Titan with the owner's KAST prefs; data and
machine — his host, his tablet, his Tailscale; path — the host list → «Desktop» tile, as the user starts a stream.
