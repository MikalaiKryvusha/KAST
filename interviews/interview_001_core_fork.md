## Контекст — что уже известно

Сегодняшний эталонный прогон (`testcases/reports/2026-09-26_F1_baseline.md`): при пропаже сети KAST сдаётся через 9,7
секунды и показывает «Код ошибки: -1». Эти 10 секунд зашиты в ядро связи — отдельный кусок кода, который KAST берёт из
чужого репозитория (`ClassicOldSong/moonlight-common-c`, лицензия GPL-3.0) и сам поменять не может. Чтобы время ожидания
бралось из настройки (ваши 60 секунд), нужна своя копия ядра с правкой. Сервер уже держит 60 секунд — эта часть готова.

Создать новый репозиторий на вашем GitHub — действие от вашего имени, поэтому спрашиваю. Своей копии ядра у вас пока нет
(проверено: `gh api repos/MikalaiKryvusha/moonlight-common-c` → 404).

### Q1. Где держать правку ядра связи?

**Answer target:** `plans/02_EPIC_reconnect.md` → «Развилки», строка «Публичный форк `moonlight-common-c`»; операционный план Ф2 (будет `plans/04_epic02_F2_*`)

**Origin:** вопрос поставил агент 2026-09-26 при закрытии фазы Ф1 эпика «переподключение»: без правки ядра не делается фаза Ф2 «удержание» — KAST не переживёт даже 20-секундный провал. Решает, где будет жить эта правка и кто её видит.

- **A) (Рекомендовано) Открытая копия ядра на вашем GitHub рядом с KAST**
  - Ситуация. KAST открыт всем на GitHub; ядро связи лежит в чужом репозитории, и 10 секунд там не поменять.
  - Действие. Агент создаёт на вашем GitHub открытую копию ядра `MikalaiKryvusha/moonlight-common-c`, вносит правку и
    подключает её к KAST.
  - Результат. На вашем GitHub рядом с KAST появляется второй открытый репозиторий; KAST собирается с вашей правкой, и
    любой, кто скачает KAST, соберёт то же самое. Так устроены Artemis и Moonlight: у каждого своя открытая копия ядра.
  - Check. `gh api repos/MikalaiKryvusha/moonlight-common-c` → `fork: true`; `.gitmodules` указывает на неё; `git clone --recursive https://github.com/MikalaiKryvusha/KAST` собирается.
- **B) Закрытая копия ядра на вашем GitHub**
  - Ситуация. Та же.
  - Действие. Агент создаёт закрытую копию ядра.
  - Результат. Правку видите только вы; но открытый KAST у посторонних не соберётся — ядро им недоступно. Если вы
    когда-нибудь раздадите собранный KAST, лицензия GPL-3.0 потребует открыть исходники ядра.
  - Check. `gh api repos/MikalaiKryvusha/moonlight-common-c` → `private: true`; клон без доступа падает на подмодуле.
- **C) Не создавать новый репозиторий — хранить правку ядра файлом-заплаткой внутри KAST**
  - Ситуация. Та же.
  - Действие. Агент кладёт правку в KAST как файл-заплатку и накладывает её на ядро при каждой сборке.
  - Результат. На вашем GitHub ничего нового; но каждое обновление ядра может ломать заплатку, а сборка становится
    сложнее — это на одну движущуюся часть больше.
  - Check. `git apply --check patches/moonlight-common-c/*.patch` проходит на текущем ядре.
